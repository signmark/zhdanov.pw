# zhdanov.pw — Personal Landing Page

Персональный лендинг-сайт, упакованный в Docker и готовый к запуску за reverse-proxy **Traefik**.

Весь сайт — один файл `index.html` (разметка, стили и скрипты внутри). Сборки нет,
зависимостей нет: правишь файл и деплоишь.

## ✏️ Правка контента

Источник всех текстов — [`CONTENT.md`](CONTENT.md). При расхождении сайта и этого файла
правится сайт, а не источник. Там же список нерешённых вопросов (какая почта каноническая
и т. п.).

### Двуязычность: две настоящие страницы

У сайта два адреса, и у каждого своя страница в репозитории:

| Адрес              | Файл            | Язык |
|--------------------|-----------------|------|
| `zhdanov.pw/`      | `index.html`    | EN   |
| `zhdanov.pw/ru/`   | `ru/index.html` | RU   |

Английский текст лежит прямо в `index.html` — это язык по умолчанию, поэтому
он рисуется без мигания. Русский текст лежит в [`i18n/ru.json`](i18n/ru.json),
а страница `ru/index.html` **собирается из него скриптом**:

```bash
npm run build:ru     # node scripts/build-ru.mjs — index.html + i18n/ru.json -> ru/index.html
```

Раньше русский текст подставлялся скриптом в браузере по адресу `/?lang=ru`.
Так поисковик русскую версию не видел вовсе: сервер отдавал английский HTML с
`canonical` на `/`. Теперь у русской версии свой адрес, свой `canonical` и
`hreflang` с обеих сторон, а старый `/?lang=ru` отдаёт 301 на `/ru/`
(см. `nginx.conf`).

Файл `ru/index.html` **в коммит входит, но руками его править не надо** —
правьте словарь и пересобирайте, иначе следующая сборка затрёт правку.

### Как править контент

Тексты помечаются в разметке атрибутом, словарь лежит в `i18n/ru.json`:

```html
<!-- 1. атрибут на элементе: data-i18n для простого текста,
        data-i18n-html — если внутри есть теги (<br>, <span>) -->
<h3 data-i18n="about.c1t">Agent-driven, review-gated</h3>
```

```json
// 2. ключ в i18n/ru.json -> strings
"about.c1t": "Агенты под ревью"
```

Ключ без пары в словаре останется английским в русской версии, и это поймает
сторож из раздела ниже. Переключатель языка в шапке — обычные ссылки на `/`
и `/ru/`, никакого подмена текста на клиенте больше нет.

## 🛠 Сборка и проверки

```bash
npm run build        # русская страница + статический CSS
npm run build:css    # только CSS (Tailwind CLI -> assets/site.css)
npm run build:ru     # только русская страница

node scripts/check-seo.mjs      # сторож: canonical, hreflang, og:image,
                                # русский текст в разметке, sitemap, robots
                                # и живая проверка nginx (настоящий 404)
python3 scripts/mutations-t17.py  # пять порч: сторож обязан краснеть
```

Стили собираются Tailwind CLI в `assets/site.css` (11 КБ) вместо
`cdn.tailwindcss.com` — того самого компилятора в браузере, который весил
сотни КБ. Файл `assets/site.css` в коммит входит.

Проверка `check-seo.mjs` поднимает настоящий nginx и смотрит коды ответов:
несуществующий адрес должен давать 404, а не главную страницу с кодом 200.

В корне лежит `googlef135278a92d1749a.html` — подтверждение прав на сайт в
Google Search Console. Он должен быть и в репозитории, и в `COPY` в
`Dockerfile`: на бою его клали руками, и пересборка контейнера его сносила.

## 🚀 Деплой одной командой

```bash
docker compose up -d --build
```

### Как это работает:
1. Docker Compose собирает легковесный образ на базе **Nginx:alpine** с оптимизированным конфигом (`nginx.conf`).
2. Контейнер автоматически подключается к вашей внешней Docker-сети `proxy` (где крутится Traefik).
3. Traefik перехватывает запросы к `zhdanov.pw` и `www.zhdanov.pw`, получает SSL-сертификат через указанный резолвер (`myresolver`) и перенаправляет трафик на порт 80 контейнера.
4. Добавлен middleware для автоматического редиректа с HTTP на HTTPS.

## 📋 Требования к хосту

- Установленный Docker и Docker Compose.
- Запущенный стек Traefik с внешней сетью под названием `proxy`.
- Созданный в Traefik `certresolver` с именем `myresolver`.
- Направленные `A`-записи домена `zhdanov.pw` и `www.zhdanov.pw` на IP-адрес вашего сервера.
